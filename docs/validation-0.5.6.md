# 0.5.6 验证记录

2026-10-17，Windows / Node 24.16.0，官方 DSH 0.2.1-alpha.5。

## 修复的问题

从公开 npm 安装 0.5.5 后，真实 Agent 的模型入口为 `run_code`，但完整提示词只有极简身份句，缺少可调用工具 SDK。直接注册、挂载预设及脚本知道工具名时的执行均可通过，因此只检查工具数量不能证明模型能使用它们。

0.5.6 将极简身份句和宿主实时生成的 PTC SDK 合并为完整提示词。通过宿主 Loader 读取官方生成器，以当前作用域的公开工具清单和输出契约生成参数、返回值与执行说明；没有调用宿主私有方法，也没有复制另一份核心依赖。仍不附加工作区指令和可选运行时上下文。

SDK 占用的上下文随工具清单增长；修复后的提示词不再只有一句话。SDK 中的文字不进行模板变量插值。

## 已验证

- 本地 26 项测试：25 通过，1 项 POSIX 执行测试在 Windows 跳过。新增用例覆盖动态工具启停、作用域、运行格式、输出类型、模板字面量、缺少契约和资源清理。
- 公开旧版基线：模型提示词缺少 SDK，验收明确失败；合成脚本已知工具名时仍能执行并返回 42，说明“能执行”和“模型看得到声明”是两项证据。
- 修复后真实 DSH Agent 的模型入口仍只有 `run_code`；提示词含当前工具 SDK，能看见合成工具声明。
- 默认函数体执行：TypeScript 类型标注、嵌套工具调用、`console.log` 与 `return` 均成功，返回值为 42；下一次执行不保留前一次局部变量。
- 可选持久模式：实际调用得到 41 → 42；不同 owner 的变量隔离，释放后清空；SDK 没有误写成函数体的 `return` 指引。
- alpha.4 的默认与持久执行复测通过，沿用该宿主原有的 SDK 文案；alpha.5 使用新版按执行格式区分的指引。
- 发布前从本地 tarball 经官方 CLI 独立安装，默认与持久桥接均通过；实际网页可在模式菜单中选择极简 PTC，无页面或控制台错误。

上述实际执行使用隔离的合成会话和 Full 权限，未更改用户会话或系统权限。没有调用真实模型，不能据此宣称模型自主选工具已经验收；原生桌面窗口也未操作。源码回归、CI、最终 npm 包与安装验收分别核对。
